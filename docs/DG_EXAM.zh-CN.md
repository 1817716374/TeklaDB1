# DG 8.95 / 9.08：目录边界、数字身份与工程关联

新增四张8.95顺序表图纸和一张9.08分节图纸的部分语义支持。当前读取文字链、属性/属性关系、已存图幅、主体类型与数字ID、模型数字引用；9.08可在工程GUID和存储版本一致时与DB1关联。视图、尺寸几何、纸面变换、完整绘图图元及生命周期尚未恢复。

## 来源与边界错误

五张图纸及其 `.dg.metadata` 来自[Trimble官方考试工程固定提交](https://github.com/TrimbleSolutionsCorporation/TSOpenAPI_Model_Exam/tree/7345e5f14c86bf94f9da073705c56526d6895c6d)。同包DB1、DB2、profdb.bin在本验证目录中复用，13个固定文件路径的ZIP成员、大小与SHA-256记录于 `tests/corpus.json`。复用文件和历史图纸不计为独立工程样本。

8.95头为固定12字节 `Xsteel  8.95`，后面立即是二进制目录记录数46。46的低字节是ASCII句点，旧代码贪婪扫描数字/句点会将版本误读为 `8.95.`，导致原始入口也失败。现在按已观察到的 `N.NN` 四字节版本字段读取，再按表长度解析目录；回归同时覆盖计数字节为句点及数字0至9，不依靠文本终止符猜测二进制边界。

四张8.95有46种记录表加一张目录，共47表；9.08为 `Xsteel# 9.08`、76字节前导、47种记录表加目录，共48表。9.08每行的附加元数据为 `24 + 16 × 引用描述符数量`，全部原样保留。容器走读与逐字节重建覆盖五张文件，不解释分配标签或附加元数据的生命周期含义。

## 字段证据

完整语义签名逐表核对宽度；9.08还逐项核对字段描述符。与9.54不同，view载荷4676字节、subject为6132字节，不能直接使用9.54几何偏移。

| 记录类型 | 载荷字节 | 当前读取 |
|---|---:|---|
| 293 | 45 | ID@0、后继@4、文字@16（28字节） |
| 298 / 296 | 110 / 37 | 字符串/数字属性及原始值 |
| 295 / 297 | 12 | 属性关系ID、属性ID、所属上下文 |
| 266 | 52 | 图幅宽/高@16/@24（double） |
| 269 | 6132 | 主体记录ID@4、类型@12、数字模型ID@16 |
| 322 | 112 | 引用ID@0、图纸上下文@4、数字模型ID@8 |

四张8.95的图幅804×557、类型3（总布置图）、空主体均与独立XML元数据一致。9.08的图幅297×210、类型1（单零件图）也与XML一致。其他主体类型保留代码，不擅自分类。图纸自身的 `DrawingGuid` 不在本轮恢复字段内；不能把文件名或工程GUID当作图纸GUID。

9.08主体和type322引用都保存ID `3040545`。它在配套DB1中对应GUID `02f6a87b-e776-431e-a2db-9f8f1865e98c`，与XML的 `MainObjectGuid` 相同；该对象的DB1编号前缀M、位置号92与XML标记 `[M.92]` 一致。这证明本样本的数字身份及字段关联，不代表任意历史记录都处于当前有效状态。

## 工程配对

`readProject` 先匹配DG的 `grProjectGuid` 和主库数据库GUID。数字ID自动配对目前仅验证了9.08，还要求DB1存储版本同为9.08，并确认ID存在；主体还检查已知对象种类。关联保留实际图纸路径、源记录ID、图纸上下文与匹配DB1身份的GUID。

四张旧8.95图纸保存工程GUID `aa364402-22b3-4b77-a990-285a1a3c1b65`，当前DB1为 `a09d32dc-547d-4f09-a597-b4bd338e81fa`。因此五张都可读取，但只建立9.08的一条主体关联和一条模型引用关联。8.95数字ID与配套旧模型仍需更多独立验证，不自动与当前模型配对。错工程GUID或改为有效8.95容器的测试副本也不会得到9.08对象关联。

未解读视图和尺寸的记录ID公开于 `unhandledViewRecordIds` / `unhandledDimensionRecordIds`；空几何集合不表示文件没有几何。配套XML现有独立的[图纸版本元数据接口](DRAWING_METADATA.zh-CN.md)，公开图纸GUID、标题、作者、图幅及已存整数，并校验工程配对；生命周期字段的运行时含义和最新版本选择仍未解释。

## 复验

```sh
python -B tools/test_drawing_exam_evidence.py --data /path/to/corpus --download --exe /path/to/tekladb1_validate --work /path/to/separate-work
```

独立的Python ElementTree读取配套XML，核对五张图幅/类型及9.08主体GUID/标记。九种变异涉及图幅、主体类型、XML宽度、主体ID、引用ID、工程GUID、有效但不同版本的容器、XML主体GUID和XML编号；恢复原文件后再次验证。人工转换的8.95副本仅是测试输入，不算新增原生样本。Windows测试与下载目录放在E盘。

新增28项合成输入测试、两个安装后消费测试和16项固定语料用例。原始重建证明字节未丢失，统计/指纹证明回归稳定；它们不等于独立几何或完整图纸真值。
