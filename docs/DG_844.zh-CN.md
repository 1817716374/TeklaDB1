# DG 8.44：可变记录尾部与文本元数据

`parseRawDatabase` 支持 `Xsteel# 8.44` 分节图纸容器，`parseDrawing` 恢复文字链、字符串/数值属性、属性关联及已存图幅。视图、主体、尺寸、图元、模型引用与生命周期仍未恢复；原始容器可读不能视作完整图纸支持。

## 固定证据

公开[AUVENT教学工程](https://btscm.fr/dicocm/C/CCF/CCF_BE_2019/AUVENT_CCF_BE_AMCR1_2019_final/drawings/)的一份 `DID54A03D14-3328-47D1-B298-9B37193B88A2.dg`，压缩16,079字节，解压104,678字节，SHA-256 `1055ed3cc3f7e6c8fe15f566eeeda09ef4db0b3d117e42862e096a3cfc93e893`。同工程 `drawing_history.log` 与此前固定的 `guid.mapper` 用作独立历史证据，来源、大小及哈希均在 `tests/corpus.json`。一份历史图纸不能证明其他8.44工程全部兼容。

## 容器

76字节头之后为47个分节，首表是逆序类型目录，其余46个表保存数据。合计662条记录（计入目录）。每个表保存负载宽度、字段描述符、带分配标记的记录及零字节结束符。当前8.44签名描述符均为0/1且首项为1。每条记录在负载之后附带 `24 + 16 × 描述符中1的数量` 字节；如视图表有5项，尾部为104字节。不能套用7.82的固定40字节尾部，也不能扫描记录里的表头魔数来推断边界。

尾部原样保存在 `RawRecord::allocatorMetadata`，其各块含义尚未证实。读取器保留头、描述符、标记、负载、尾部和结束符；真实语料测试将它们逐字节重建为原始解压文件。未知描述符、截断、超出解压上限、错误目录与非法结束符均失败；语义入口另检查完整表宽度及引用描述符签名。旧版容器行为保持不变。

## 文本与属性

字符串表293的ID/续块引用位于payload0/4，文字从16起，最多28字节。360个块重组为41条完整根字符串，包含标记XML。表298保存4个命名字符串属性，表296保存1个数值属性，295/297保存5条关联。保留原始字符串字节，不将XML求值或转为最终显示文字。链断裂、循环、重复ID及错误属性引用被拒绝。

该图纸 `grProjectGuid` 原值带大写 `ID` 前缀。仅对8.44识别此形式，`Drawing::projectGuid` 去掉前缀以提供36字节GUID，`DrawingProperty::stringValue` 保留完整原文。`grFileName` 从文件内容读取，不由输入路径生成。表266保存的图幅为410×287；这个值未与最终纸张/打印边界独立对照。

图内标记XML保存 `PART_POS=S14`，独立历史日志有对应 `[S.14]` 删除记录。工程GUID `152F6ED8-4DAA-4276-B493-0AEA86E0BD65` 与 `guid.mapper` 中一条明确的历史映射源相符。验证器检查这两个外部证据；分别改变图内标记、工程GUID、日志标记或映射源GUID均必须失败。这只证明文字和历史身份的对应，不证明当前模型状态或图纸仍有效。

## 尚未解读

一条视图记录和13条尺寸记录的ID分别进入 `unhandledViewRecordIds` / `unhandledDimensionRecordIds`；主体、尺寸链、模型引用及其他图元保留在原始表中，诊断说明空语义集合不能理解为没有这些源记录。图纸工程GUID与当前及已取回历史DB1头均不吻合；不按目录、文件名、旧数字ID或未经证明的传递GUID映射自动建立模型关联。下一步需要相同状态的模型和独立出图，确认可变尾部中的引用、坐标与尺寸布局、纸面变换及生命周期。
