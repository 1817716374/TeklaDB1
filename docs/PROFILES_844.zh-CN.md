# Xsteel 8.44 型材字段与 IFC 对照

修正前，8.44 读取器把构件定义中的编号前缀当作型材族，造成 `IPE160` 被读成 `PT160`、`IPE120` 被读成 `PN120`。这一问题会让后续型材目录查询和几何构造使用错误输入。

下面均为定义记录 **payload 的零起始偏移**，不包含分配标记。主库表245、组件库表215的记录宽度均为322字节。

| 字段 | 偏移 | 字节数 |
|---|---:|---:|
| 构件名称 | 54 | 22 |
| 型材族 | 76 | 64 |
| 尺寸字符串链引用 | 140 | 4 |
| 编号前缀（本次不新增公开语义） | 144 | 22 |
| 现有 secondaryName 字段 | 166 | 62 |
| 材料 | 228 | 32 |
| 后续表面处理字符串区域 | 260 | 62 |

型材仍由“保存的族名 + 尺寸字符串链”组成。缺失链节点或循环引用会使语义解析失败并清空结果；零引用允许没有尺寸后缀。名称、族名和材料即使占满各自字段，也不能吞入下一个字段。未知字段继续通过原始数据库 API 保留。本次没有把8.44完整字段签名、编号分配或表面处理标为已恢复。

## 独立证据

公开[AUVENT工程目录](https://btscm.fr/dicocm/C/CCF/CCF_BE_2019/AUVENT_CCF_BE_AMCR1_2019_final/)中的 `Philippe_Boineau_CCF_BE_AMCR_2019.db1.bak` 与 `IFC/PB_AUVENT.ifc` 固定在语料清单中，保存来源、大小和SHA-256，第三方文件不随源码分发。

`profile844_evidence` 从 IFC2X3 实际内容读取 GUID、产品名称、型材及放置坐标，按 GUID 配对58个构件。58个名称、58个世界坐标原点、19个完整型材字符串均吻合；坐标容差为0.002毫米。型材包括 IPE160、IPE120、TUBE-60.3*3.2、L40*4、UPF-100*50*4。IFC对板件生成的型材字符串包含宽度，不能当作DB1保存的字符串，因此没有将这些生成后缀用于本次精确字符串比较。

`tools/test_profile844_evidence.py` 对固定输入重新校验哈希，并确认以下变异不能通过独立检查：

- 把实际 IPE 族改成原先误读的 PT 前缀。
- 将真实构件原点移动100毫米。
- 把 IFC 的 IPE160 改成 IPE999。

主库和组件库另有字段满宽、缺失尺寸链、链后继缺失及循环引用回归。7份同工程历史快照的新旧解析输出逐构件比较，仅 `profile` 改变；这些快照不能算7个独立工程。

## 剩余边界

58个原点吻合不证明所有坐标基、加工后长度、实体几何和生命周期均一致。IFC导出日志的数字ID与历史DB1中的数字ID存在不同偏移，不能按数字ID直接配对，也不能靠一个统一偏移修正。IDRM转换仍待验证。后续恢复的79个螺栓组和201个位置见[8.44螺栓证据](BOLTS_844.zh-CN.md)。
