# DG 9.50 原始容器证据与边界

## 样本与读取状态

固定语料新增公开的 Tekla Structures 2023 SP4 工程 `Abri-Moto-VCCF25`，来源为 [BTSCM 工程压缩包](https://btscm.fr/dicocm/T/TEKLA_fichiers/Abri-Moto-VCCF25.zip)。归档 URL、字节数和 SHA-256，以及工程主 DB1、DB2、xslib、profdb、environment/options、9 张 DG 和 6 份 `.dg.metadata` 均记录在 `tests/corpus.json`。测试数据由语料脚本下载到源码树以外，不随库分发。

该工程的 DG 文件为 gzip 流。解压后以 `Xsteel# 9.50` 开头，随后是 48 个 section：一个目录和 47 个物理表。九张图纸各有 130、897、681、704、895、543、130、592、1001 条记录，合计 5,573 条；897 是其中一张图纸的数量，不是工程总数。通用 raw API 保留所有 section、记录和解压后完整镜像；项目入口现将九张图纸读为 `PartialSemantic`。

对九个文件逐 section 独立走读后，确认 48 项目录/宽度/字段描述符签名完全一致。目录记录在不同图纸中可能正序或逆序；解析器现先规范物理表编号，再按该 9.50 固定签名严格校验。与当前 9.54 语义入口的宽度向量比较，除 table 259、260、269 外，其余物理表宽度相同；这三表的 9.50 宽度分别为 664、4740、6148 字节，对照 9.54 的 712、4788、6196 字节。9.50 这三表的字段描述符数量分别为 101、652、804；现有 9.54 签名检查没有固定描述符数量。因此不把9.54的 subject/view/dimension 偏移推广到9.50。

9.50 语义入口读取 type-293 字符串及 continuation、type-295/297 字符串属性链接、type-298 字符串/数值属性、type-266 图幅，以及 type-269 的一项主体记录。主体记录的已观察字段为：type@0、记录 ID@4、保留字@8、主体类型@12、16字节身份@16；该布局仅对本工程 9.50 签名和已观察类型码解码。类型1映射为单零件，类型2映射为装配；两者的16字节值按文件字节顺序格式化为GUID。类型7记录没有主体GUID，保留为未知类别。未知类型码、非零保留字和重复主体记录都保留raw，不套用该字段解释。

## 视图上下文与直线尺寸锚点

同一 9.50 工程的七张含尺寸图纸共有 19 个视图、136 条 type-256 记录和 67 条 type-257 尺寸集记录。type-260 的 type/record ID/context 位于 @0/@4/@8；type-256 的 type/record ID/context/set ID/subtype 位于 @0/@4/@8/@12/@16，type-257 的 type/record ID/context 位于 @0/@4/@8。解析器要求 9.50 固定签名中的 type-260/256/257 宽度分别为 4740/1496/144 字节，并校验所有已解码尺寸与尺寸集的 context 都唯一命中视图、尺寸 set ID 命中同 context 的尺寸集。七张图中这些引用全部闭合，ID 均唯一。

type-256 的 subtype 1 共119条，恢复存储起点、终点、up方向和距离；17条 subtype 0 继续留作 raw。所有119条方向向量在样本中均为单位 XY 向量，其中27条端点共面，因此只对这27条给出诊断性 `projectedLength`。这证明这些字节可稳定读取和执行文件内关联检查，不证明纸面尺寸文本、比例/单位换算、缩短规则或标注渲染。type-260 仅公开 ID/context 前缀，`DrawingView::geometryDecoded` 为 false，其他视图坐标和范围保持原始数据。

本工程9张图纸各有一条 type-269 记录，类型计数为1:2、2:1、7:6。六份 sidecar 的 `DrawingType` 与对应 DG 主体类型相同。三条单对象主体 GUID 均在所选主 DB1 identity 表中唯一命中：两条命中当前解析器保留为 `unhandledPartIds` 的部件身份，一条命中已解析装配身份。这证明本工程中的字段和跨文件 GUID 精确匹配，但两张部件仍因 9.50 DB1 identity class 未解释而没有完整类别语义。

九张图纸合计得到 365 条字符串、35 项属性、36 条属性链接和 9 个图幅；六份 `.dg.metadata` 的宽高都与对应 DG 图幅相同。9张DG的 `grProjectGuid` 与所选DB1 GUID为0/9匹配，因此不把DG文件整体配对到DB1，也不使用其中其它模型引用。另一方面，3张单对象图纸的主体GUID在DB1身份表中各有唯一精确命中，且分别落在零件表两条、装配表一条。工程入口只为这三条建立 `DirectSubjectGuidIdentity` 主体关联，并保留project-GUID不匹配诊断；其余六个多对象主体没有对象GUID，不关联。三份sidecar的 `MainObjectGuid` 与DG主体GUID不同，因此六条metadata→DG仍只有 `FilenameAndSheet` 文件级证据，不继承主体关联。视图、尺寸、其它模型引用和绘图图元继续保留raw。

语料回归检查主 DB1 明确选择、9.50 DB2 九条编号系列、同名且 GUID 相符的 DB1/DB2 配对、42 个 profdb 名称关联、environment/options 读取，以及九张 DG 的部分语义投影。六份图纸 metadata 均可解析，其中一份使用 Windows-1252；解析字段转为 UTF-8，`rawXml` 仍保留原字节，并在诊断中记录编码回退。六份 sidecar 都与唯一同名 DG 的内部保存文件名和图幅尺寸吻合，因此建立 `FilenameAndSheet` 文件级关联。三条 DG 主体 GUID 唯一命中 DB1 身份且与零件/装配表相符，按 `DirectSubjectGuidIdentity` 建立窄范围对象关系；project GUID 不匹配仍阻止工程级配对及其它引用关联。metadata 的 `MainObjectGuid` 与本样本的三条 subject GUID 不同，因此不会取得 `modelObjectId`。另有六个 `DrawingGuid` 分别唯一命中 DB1 identity 表，ID 为 457401、458342、452508、458306、457278、457467；这些身份不在已解析的 part 或 assembly 表中。工程 API 将精确匹配作为 `drawingGuidIdentityId` 暴露，但不赋予身份类型或生命周期语义。

## 尚未恢复

- DG 9.50 的完整图元、视图几何和非主体模型引用，以及 subtype 0 尺寸记录。type-269 单对象主体只在GUID唯一命中且零件/装配表类别相符时建立直接身份关系；project GUID不匹配仍禁止整图配对。该直接关联仅有此一个9.50工程证据，跨工程可复现性仍待验证。容器及已解码的主体/字符串/属性/图幅只是部分语义，不代表其余记录已解析。
- 该工程 DB1 可连接解析 177 条 part、106 条 assembly、109 条 bolt group、22 个 component、6006 个 profile 和 715 个属性；177 条 part 都因 identity type 未知而保留在 `unhandledPartIds`，没有分类进 `actualPartIds`。独立 IFC 对照命中 158/177 个 part、99/106 个 assembly 和 108/109 个 bolt group；另有 55 个 IFCFASTENER identity 尚不能分类。已命中的 266 条 IFC 聚合边中，158 条的 DB1 owner 与 IFC 父子关系相符。这支持身份/类别归属检查，不验证存储几何与 IFC 几何等价。
- 同一归档中的 `Nouveau modèle.db2` 是经签名校验的 8.44 空编号快照，GUID 与配套 8.44 DB1 一致；8.44 非空 DB2 系列、对象分配与比较快照仍未恢复。

本样本支持 9.50 gzip DG 的固定语料签名、raw 保留及主体/字符串/属性/图幅部分读取。3条单对象主体 GUID 唯一命中同工程 DB1 身份且对象表类别相符，作为窄范围 direct subject identity 关联；它不等同工程级配对或图纸版本状态判断。六条 metadata→DG 文件关系仍由文件名/图幅确认，另有六条 DrawingGuid→DB1 identity 精确匹配，但该 identity 的对象角色未知。没有证明完整图纸语义、其它 DG→DB1 引用或模型当前状态。
