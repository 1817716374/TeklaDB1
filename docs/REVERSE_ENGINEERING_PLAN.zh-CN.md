# Tekla DB1 完整逆向路线图

本文档是持续更新的工作记录。每发现一个新版本、表布局或语义边界，都要先修改本文档，再扩大实现范围。

## 2026-09-26：多格式长期目标（进行中）

用户明确要求将目标扩展为全部关联格式，而非仅 DB1。验收范围包括 DB1/xslib、DB2 编号、DBV 环境与选项、各类目录、Shapes/TEZ、DG 图纸、工程元数据及可验证的跨文件关联。仅发现文件或保留原始容器不计为语义完成；逐格式记录已恢复的字段、版本证据、尚未覆盖的对象与独立真值。

当前优先级为 DB2 与 DG。公开培训模型的 DG 9.54 使用无 magic 的顺序定长表，不能套用现代 DB1 section 扫描。DB2 则使用带表 ID 的顺序表，表后有结束标记，部分表 ID 大于一千万；现有 legacy 扫描会漏掉这些表。先恢复严格容器边界、DB2 编号系列和 DG 字符串/属性/工程 GUID 关联，再继续恢复编号对象分配、视图、尺寸、标记与图元。此次工作不将局部语义阶段标记为全格式完成。

下一阶段推进 DBV：30 份 environment.db 对应 9 表/15 表两套字段签名；60 份 options 库共享 9 表签名。DBV 使用单字节表尾，部分样本的记录标签为 1，不能只按 DB1 的 4/12 标签读取。计划恢复环境类别、属性名称/标签/存储类型、属性与类别关联、整数选项列表，以及 options 库的键名、值类型和成对存储值。属性元数据标志及成对值的默认/当前优先级尚未由差分实验确认，必须保留原值而不臆造有效值；浮点/字符串选项列表目前无非空真实样本。原始数据与未覆盖字段继续公开。

## 2026-09-24：DB1 可靠性与多文件工程入口

DG 后续范围：已在现有 7 份 DG 中核对 19 条 type-260 视图记录的两组正交坐标基，并确认所有 type-322 模型引用的 context 均落到视图。type-269 图纸主体 GUID 在 DB1 中分别对应钢板或装配；3 份 DG 只有零类型占位头，无视图。计划增加视图坐标基、范围/深度和主体关联，通过同包 `.vi` 设置核对一组 6 个范围值，并以 DB1 对象类型与坐标方向交叉验证。比例、纸面原点、缩短和完整投影图元仍需独立真值，不能凭外观猜测完成重绘。

长期方向是离线 Tekla 文件互操作库：独立文件读取 + 模型目录关联。保持现有 TeklaDB1 API 兼容，逐步加入工程级资源索引；不将 DB2、DBV 或 DG 的原始字节读取宣称为完整语义支持。

本轮优先修复现代节 magic 碰撞、schema 字段签名未验证、未知版本误接受、主数据库选择歧义、构件类型/诊断和克隆后的构建测试。网上公开样本以固定提交、下载 URL、SHA-256 和预期结果记录，数据放在仓库外，不把第三方模型纳入源码发行。

验收包括：合成异常输入的 CTest 回归、公开实际模型跨版本读取、安装后独立消费，以及多文件工程清单的确定性与关联诊断。几何近似与尚未支持的对象必须显式报告；历史“完成”记录不代表所有 Tekla 对象及未来布局均已支持。新找到的 7.82、8.95、9.52、9.60 公开样本用于验证或记录边界。

本轮实现：28 个默认 CTest 用例、可选 OCCT 简单体积/网格验收、282 个外部文件的散列清单及 298 个公开语料回归用例。其中 28 份主库和 28 份组件库读取通过，另 2 份 7.82 主库与 2 份组件库明确拒绝语义解析，raw 层可读。所有样本可通过 `tools/corpus.py --download` 重新获取，无第三方模型字节进入仓库。

公开语料确认早期现代表存在 1 字节结束标记；DBV 名称前的整数是名称长度，不是版本。8.95 组件库的未使用倒角槽存在 NaN，不能对未使用槽一律按有效尺寸拒绝：有效坐标仍要求有限值，无法用于构形的活动倒角保留并诊断。`tekla::readProject` 聚合配套目录、raw DB2/DBV、同名配对与图纸清单；`TeklaFormats` 包名与现有 `TeklaDB1` 包共存。

后续验收缺口仍包括：7.82 语义映射、8.44 的独立完整签名复验、现代路径/复杂实体与钢筋专用类型、DB2 编号语义、DG 图纸，以及真实模型的 Tekla/IFC 几何真值。不得用这里的回归通过数替代这些缺口。

## 完成定义

“全部逆向成功”至少同时满足：

1. 能识别并安全遍历已收集的所有 DB1、xslib 和目录容器，未知布局必须给出明确诊断，不能越界猜读。
2. 主模型中的实体、参数、坐标、属性、GUID、所有权、装配和组件关系能够形成稳定的中立对象图。
3. 线性构件、板、折板、轮廓板、钢筋、螺栓、焊缝、切割、布尔体、拟合、控制对象和自定义组件均有明确语义或明确记录为尚未覆盖。
4. `profdb.bin`、`matdb.bin`、`screwdb.db`、`assdb.db`、`profitab.inp`、Shapes XML、ShapeGeometries TEZ 和 `xslib.db1` 均有独立公开解析 API。
5. 不使用 OCC 时返回足以重建几何的参数化描述；启用可选 OCC 模块时能生成拓扑实体并输出可验证网格。
6. 不同版本通过存储版本与表结构签名选择 schema，不依赖单一固定表数量。
7. 每类记录都要有真实样本、边界检查、引用完整性检查和跨版本回归；可构造几何的对象还要与 IFC 或其他真值比较包围盒、体积和位置。

## 实现状态与验收

### A. 独立核心库（完成）

- 中立命名空间、头文件和 CMake 包。
- zlib 是核心唯一依赖。
- Windows 使用宽字符入口验证中文路径；Linux 使用 UTF-8 路径。
- 7.30 与 9.52 现有样本回归结果不得退化。

### B. 跨版本 schema 映射（已覆盖现有语料）

- 对每张表建立 `(负载尺寸、字段数量、前后邻接、记录标签、引用分布)` 指纹。
- 用序列对齐找到 8.44/8.95/9.65/9.66 与 9.52 的插入、删除和变更表。
- 把解析器中的硬编码 ordinal 收敛为命名表角色，再由版本 schema 解析到实际 ordinal。
- 首先恢复点、坐标基、身份、字符串、构件定义与构件实例，再逐类扩展。

当前结果：

- 9.65 和 9.66 的已使用语义表与 9.52 保持相同 ordinal 和完整表签名；它们分别在末尾追加 15 和 16 张表。核心解析器验证实际使用表的签名，不限制总表数。
- 真实 9.65 模板已成功恢复 7,176 个实体构件、5,529 个操作构件、2,682 组螺栓、7,982 条焊缝、2,359 个装配和 2,272 个组件。
- 8.95 的身份、构件定义、332 字节轮廓、螺栓定义和字符串属性使用独立角色映射；真实模板恢复 1,053 个实体构件、62 个操作构件、395 组螺栓和 192 条焊缝。
- 8.44 使用独立角色映射。旧轮廓块的首点是隐含局部原点，后续分块连续拼接；真实模板恢复 462 个实体构件、107 个操作构件和 112 条焊缝。
- 所有未命名表仍可通过原始容器 API 逐字节读取，避免将未经验证的偏移暴露为伪语义。

### C. 外部目录（完成现有语料）

- `profdb.bin`：版本 9/10、十表结构、参数化型材、固定轮廓、多环与倒角。
- `matdb.bin`：版本 3、六表结构、材料层级、名称、密度和强度属性。
- `screwdb.db`：版本 3、116 字节记录，恢复螺栓尺寸、标准与属性。
- `assdb.db`：版本 3、355 字节记录，恢复螺栓组件及其零件组合。
- `profitab.inp` 与 `.clb`：文本型参数化截面定义及环境覆盖规则。
- Shapes XML/TEZ：名称、GUID、包围盒、几何引用、点、面和内环。
- `pgdb.bin`：五表 Sketch Solver 结果、链式名称、点块、点、圆角和精确截面。
- `TeklaStructuresModel.xml`：版本、环境、语言和模型搜索路径。

### D. xslib 与对象图（完成现有语料）

- 区分模型主库和组件库 schema。
- 恢复动态值、公式、输入参数、组件定义、实例和生成子对象之间的引用。
- 对模型目录、环境目录和模型内覆盖目录建立明确的查找优先级。

17 份 7.30 至 9.66 的 `xslib.db1` 已全部通过语义回归；最大样本恢复 11,297 个参数定义和 520 个自定义组件定义。长公式按链式字符串块完整重组。

### E. 几何（可选后端完成，未知自定义型材显式保留）

- 核心模块公开与 CAD 内核无关的曲线、轮廓、扫掠、放样、布尔、孔和网格描述。
- OCC 模块独立目标、可关闭；不得让 `TopoDS_Shape` 泄漏到核心 API。
- 对每个实体保留原始参数和诊断，失败对象不得静默丢弃。

当前 OCCT 回归：7.30 实体构件 1,240/1,240 构形成功；9.52 实体构件 2,014/2,014 构形成功；8.95 在缺失若干专有自定义型材定义的环境模板中精确构形 438/1,053，其余 615 个构件均保留解析结果、对象 ID 和诊断，不以猜测包围盒冒充精确几何。OCC 三角化由线性/角度误差驱动，不生成固定级数的 LOD。

### F. 验证与发布边界（本次可执行项已完成）

- Windows x64、Linux x86_64、Linux ARM64 核心库构建。
- 截断输入测试，确认读取失败可诊断且不会越界崩溃。
- 大模型峰值内存与解析吞吐基准。
- 安装包导出及独立下游 `find_package` 消费验证。

Windows x64 当前基准使用 14.21 MiB 压缩、49.94 MiB 解压、999,939 条原始记录的 9.65 模型：完整语义解析约 3.1 秒，峰值工作集约 242.6 MiB。优化前为约 15.2 秒和 264.3 MiB；所有权预索引消除了组件与身份表的二次方扫描，关联索引避免重复复制记录，流式 GZIP 解压不再常驻整份压缩输入。结果数量与优化前一致。

核心库已经在 Windows x64、Linux x86_64 和 Linux ARM64 实机编译通过。Windows x64 的可选 OCCT 后端及安装后外部消费项目也已编译、加载并完成真实模型构形/三角化。两台 Linux 构建机目前没有 OCCT 开发包，因此 Linux OCCT 目标仍缺少实机链接验证。

对主模型 DB1、`pgdb.bin`、`matdb.bin` 和 TEZ 各取最大样本，在 15 个边界位置截断，共执行 60 次独立进程读取；全部正常返回成功或可诊断失败，没有异常退出。许可证仍由仓库所有者在首次公开发布前确定，当前不对外发布。

## 仍然存在的边界

- 私有格式没有公开 schema；新 Tekla 版本或尚未收集的对象类型必须以新样本验证后才能命名字段。
- 8.44 样本未包含可验证的螺栓组，因而不把未知表强行命名为螺栓语义。
- 8.95 的旧 schema 没有已验证的 bolt-layer 字段映射；螺栓实体可恢复，孔与具体构件的关联仍通过诊断说明。
- 若模型只引用环境中的专有自定义型材，而模型目录没有相应 `profdb.bin`、`pgdb.bin`、CLB 或 Shape 几何，无法从名称唯一反推真实截面；这类构件不做伪精确构形。
- `DBV` 已恢复环境定义/类别/整数选项及 typed options 成对槽位；仍缺元数据标志、字符串定义值、非整数选项记录、有效值优先级与受控修改真值。详情见 `RELATED_FORMATS.zh-CN.md`。
