# DB1 7.64：U52 主库、组件库与独立 IFC 证据

`parseModelFile` 和 `parseComponentLibrary` 增加 Xsteel 存储版本 **7.64**，工程入口将两者标为 `PartialSemantic`。主库必须为217节，组件库必须为187节；不把未知版本或任意相近表布局当作受支持版本。

## 来源与布局

公开教学工程：[U52 ZIP](https://btscm.fr/dicocm/R/realisations/u52_2007vierge.zip)。外层698,895字节，SHA-256为 `e146458c37e73c6488184a971630296b12629a611fb1d87d848a197b60060a2c`。`tests/corpus.json` 固定主库、组件库及其备份、同包7.30主库快照和嵌套BIMsight包里的IFC，共六个文件；每层归档和成员均检查大小及哈希。第三方文件不随仓库分发。

7.64的构件定义、身份、构件记录宽度为380、63、56字节，与7.82共享经签名检查的字段读取。焊缝定义表不同：7.64主库/组件库位于188/158，7.82位于226/196。实现单独选择该角色，不用版本字符串替换伪装成7.82。

原生主库读出67个实际构件、9个操作构件、20个独立螺栓、21条焊缝、57个装配；组件库读出5个实际构件。这些数量及指纹是回归基线，不能单独证明字段语义。7条焊缝定义另做原始记录偏移一致性检查，但没有独立的焊缝工艺真值。

## 独立核对链

同包 `U52_2007V4.ifc` 是2012年的 IFC2X3 导出，包含66个构件和20个紧固件。当前7.64主库的构件GUID与该导出全部不同，因此不能直接按GUID匹配当前主库。

测试先将IFC的66个GUID与同包7.30快照匹配，并验证IFC的 `TS_` 对象编号；再检查7.30与7.64全部67个构件的编号、名称、截面、材料、类别、端点、原点、方向、长度和已存轮廓一致。只有在此样本限定的核对链成立后，才将IFC坐标用于7.64验证。

- 66个构件的名称、材料、类别、起点、终点与放置原点吻合，坐标容差0.002毫米。
- 20个IFC紧固件的对象编号对应独立螺栓，放置原点吻合；头、螺母、孔及完整螺栓几何未验证。
- 44个截面名称完全相同。其余22个有PLAT别名、宽度或尺寸格式差异，不计入独立截面语义验证。
- 编号10123的构件没有出现在这份IFC中；不强配，也不据此判为失效对象。

7.64字符串接口保持现有按字节读取行为。该法国样本的三个带重音名称采用单字节编码，7.30读取路径返回UTF-8；测试仅按样本可验证的字符范围转码比较。**这不是所有7.64文件都使用同一码页的证据，也没有改变公共接口的编码约定。**

## 边界

目前只有一个7.64工程及其备份，备份不是独立工程。表面处理与自定义组件定义表在这份样本中为空：共享字段路径有合成测试，但没有新增的7.64非空语义证据。钢筋、复杂加工/轮廓、完整实体几何和生命周期仍有缺口。

本次不扩大DB2或DG的版本支持，也不新增7.64的自动编号配对。IDRM的GUID转换、最终有效编号和跨工程身份迁移均未验证。上述IFC核对关系仅存在于测试代码，不会作为通用配对规则进入 `readProject`。

## 可复现检查

新增43项合成正常/异常输入检查，包括两种库布局、焊缝角色、错误节数、错误字段签名、引用断链和失败后清空结果；安装后的消费测试覆盖主库、组件库与拒绝损坏输入。公开语料增加11项回归，原有783文件、1,658用例的定义和预期值保持不变。

```sh
python -B tools/test_schema764_evidence.py --data /path/to/external-corpus --download --exe /path/to/tekladb1_validate --work /path/to/external-tests
```

该脚本执行原样对照、9项IFC证据扰动以及不支持版本/截断输入检查，共14项；IFC修改包括GUID、对象编号、名称、材料、类别、端点、截面、单位和紧固件位置。全部恢复后再次执行原样对照，避免仅验证“任何输入都会失败”。

本次本地验证：C++17/C++20各520项、MSVC/OCCT 528项、安装核心32项/OCCT 39项全部通过；全部1,669项固定语料通过。上述14项原生/IFC检查在MinGW C++17/20及MSVC分别通过。远端CI状态以PR所链接的实际运行结果为准。
