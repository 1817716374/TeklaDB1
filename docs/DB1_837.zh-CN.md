# DB1 8.37 主模型的有限语义

`parseModelFile` 和 `parseComponentLibrary` 现可读取同一个公开练习工程中的 8.37 主库和 `xslib.db1`。主库采用279个分节，组件库247个；解析器对已选取的基础表检查记录宽度、字段描述符范围及跨表引用，并恢复常见构件、焊缝、装配、组件和属性投影。

## 样本回归

样本来自 Trimble [Exercise 8 官方练习页](https://developer.tekla.com/documentation/exercise-8-add-text-drawing)链接的工程模型包。文件和归档不进入 Git；URL、成员路径、字节数与 SHA-256 固定在 `tests/corpus.json`，工具按需下载到外部语料目录。

当前解析回归得到234个构件、270条焊缝、108个装配、18个组件和668个属性；基础表引用通过解析器的严格连接检查。它们是该样本的解析基线，尚无 Tekla Open API 导出或 IFC 结果作独立字段真值，不能作为8.37语义完全恢复的证据。

同包 `xslib.db1` 的固定回归解析出63条存储的part记录，其中58个实际构件、5个操作件；此外有29条焊缝、15个装配、22个组件、836个属性和292个参数定义。组件库复用了与8.44组件库相同的已识别旧布局表号，并由该8.37样本中的表长度及基本引用完整性检查支撑；目前只有这一份8.37组件库样本，因此计数是解析基线，不是字段真值。

## 保留的边界

- 螺栓定义与螺栓组表不进入语义投影，需通过 `parseRawDatabase` 读取原始数据。
- 8.37组件库没有经过同版本独立导出核对的表字段角色、生命周期和跨文件对象归属；暂不据此建立主库/xslib对象关联。
- 工程入口只确认同目录主库与 `xslib.db1` 的文件配对，并将组件库标为有限语义；尚未验证主库对象到组件实例或组件内部零件的ID/GUID映射。
- 所有者、身份分类、部分类型/字段含义和生命周期仍需相同版本的独立导出核对。
- 文件中的 8.37 DB2 仅为空编号快照支持，非空记录仍被拒绝；见 [相关格式边界](RELATED_FORMATS.zh-CN.md)。

本次仅增加固定实样的解析与结构回归，不把相邻版本布局外推到语料之外的8.37文件。
